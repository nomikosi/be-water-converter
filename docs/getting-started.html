About

This is a project made for fun: I always wanted to create an IntelliJ plugin. If you find an issue, feel free to report it or send a pull request on GitHub, or message me directly.

If you have any other ideas for improvements, feel free to share them at hello@nomikosi.dev.

1. Install the plugin

Open your JetBrains IDE, go to Settings → Plugins → Marketplace, search for Be Water JSON YAML Converter, and click Install. Restart the IDE when prompted.

2. Open the tool window

Click the Be Water tab on the right side bar, or go to Tools → Be Water Converter.

3. Load your data

  • Paste text into the input editor.
  • Drag and drop a file onto the input editor.
  • Open a file with the folder button on the toolbar.
  • Right-click a file in the Project view, or a selection in any editor, and choose Open in Be Water Converter.

The source format is detected from the file extension, or from the content itself for pasted text; for CSV the delimiter (comma, semicolon or tab) is detected as well.

4. Convert

Choose the source format under From and the target format under To, then click Convert or press Ctrl+Enter.

To skip the tool window, right-click a file or a selection and choose Convert with Be Water: the result opens as a scratch file, in a real IDE editor.

5. Decode a Protobuf payload

Choose Protobuf payload under From and paste the binary message as hex (08 96 01) or base64 (CJYB). Without a schema it is decoded by field number, as protoc --decode_raw does. To decode it by name, click Choose .proto… in the options bar and pick the message type under Message.

Keyboard shortcuts

These work while the focus is inside the Be Water tool window, its editors included:

  • Ctrl+Enter converts the input to the selected output format.
  • Ctrl+Shift+S saves the output to a file.
  • Ctrl+F opens a find bar for the focused editor: Enter finds the next match, Shift+Enter the previous one, and Esc closes it.

Convert, Format Input, Copy Output, Open File and Save Output are also IDE actions: search for Be Water in Find Action, or give them shortcuts of your own in Settings → Keymap.

Toolbar

  • Swap, between From and To, exchanges input and output when the output can be read back as input. Generated Java POJO, Kotlin and JSON Schema output cannot, and a Protobuf payload is decoded, never written.
  • Format tidies the input in its own format (see below).
  • Copy copies the output; Clear empties both editors and resets the formats.
  • Open loads a file into the input; Save writes the output to a file.
  • Split switches between side-by-side and stacked editors; Soft-wrap wraps long lines in both.
  • Open in editor opens the output as a scratch file, in a real IDE editor.
  • Compare opens the IDE's diff viewer on the input and the output, both as canonical JSON: the same data in YAML and JSON compares as equal, so only real differences show.
  • History lists the last 20 conversions; choosing one restores both editors, their formats and the options. The current state is saved first, so a restore can be undone.
  • While a conversion runs, Convert becomes Cancel.

Options

The options bar below the toolbar always shows Sort keys and Filter; the other options appear when the selected formats use them. All of them except the filter and a payload's schema are remembered across IDE restarts.

  • Sort keys orders object keys alphabetically. Filter converts only part of a document, chosen by a path such as users[0].name.
  • CSV output: FLAT_FIRST expands the first array only, and CROSS_JOIN gives the full Cartesian product. Above the Row warning threshold, a conversion asks before running, in either mode.
  • CSV on either side: the Delimiter, comma, semicolon or tab.
  • CSV or XML input: Infer types turns values that look like numbers, booleans or null into typed JSON values; a leading-zero value such as 007 stays a string.
  • Java POJO and Kotlin output: Detect dates types ISO-8601 values as LocalDate, LocalDateTime or OffsetDateTime, and Java POJO output can add Lombok annotations (@Data, @NoArgsConstructor and @AllArgsConstructor).
  • Protobuf payload input: the Schema, chosen with Choose .proto…, and the Message type the payload holds.

Input leniency

JSON input may hold comments, trailing commas, single quotes and unquoted field names, and truncated JSON is repaired: unclosed brackets and strings are closed. Multi-document YAML, separated by --- as Kubernetes manifests are, converts to a JSON array.

Format

The Format button lays the input out again in its own format without changing what it says. XML is re-indented only where an element holds nothing but other elements, so text mixed with elements is kept as written.

Where a new layout would change the data, Format refuses and leaves the editor alone: a TOML date or hex number, YAML .inf, or a number that would be written back differently, such as 1.5e1 as 15. Before it drops the comments of a YAML, TOML or JSON document, it says how many and asks first.
